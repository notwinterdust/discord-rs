# Conventions

To contibute to this project, there is a set of rules to follow :

## Git

For git commits, you should be able to follow the [conventionnal commit
messages](https://www.conventionalcommits.org/en/v1.0.0/). And avoid using
bullets points for description messages, instead write a small summary that
explains what is changed, why was it changed, and why you s
pecifically choose that solution. Each commit have over 1,000 deletion or
1,000 addition to ease reviewing the code. For pull requests, you are
obligated to create an issue before making one, the pull requests should
closes the issue.

## AI-assisted code

While we don't necessarly condone the use of AI into coding, we still make
a dinstinct differation between 'developping' and 'coding'. Coding for us
is just a language that can be done by the AI, but 'developping' a.k.a. all
logical decisions and solutions are to be human. So don't abuse the "AI
fixe this" ;)

## Crates

While it is possible to add a crate, I (@notwinterdust) personally have a
preference for the standard. (I know that it is stupid, but I hate to be
dependant)



Not following one of these conventions would likely get you ignored, or
worst case scenario blacklisted D:
